# Goal 简报：本机（machine-A）· 线 A：工作流与编排

> 本简报是 **goal 模式的输入**：它定义本机的持久目标、约束与完成标准。
> 权威任务源仍是 `docs/plan/two-machine-workstreams.md`（第 2 节任务表、第 3 节契约、第 4 节批次）。
> 两机协调状态：`docs/plan/ledger/*.json`。

## 目标

以「公司工作流」为核心的企业 AI 平台（Octop 分叉），**本机完成线 A 的全部 24 项开发任务（A-01…A-24），按 6 个批次顺序推进**，每批次通过验收门禁后合入 `main`。

三条主线不可偏离：
1. **非技术员工能方便地搭建工作流**（向导 + 画布 + 自然语言生成）；
2. **搭好后能方便地用**（运行中提问、产出审核、收件箱一处处理、逐节点排障）；
3. **工作流能持续改进**（自改进提案 + 从用户纠正中学习），且改进走「影子→灰度→提升」治理链。

## 约束（违反即返工）

1. 平台核心是**公司工作流**；知识库、工具、模型、连接器、助手、市场都为工作流服务。
2. 权限是**四层**：公司 / 部门 / 个人 / 单独授权；必须有「部门负责人管理本部门资源」这一层。
3. **只改 A 线拥有的文件**（契约 5）：`workflow_compiler.py`、`workbuddy_runtime.py`、`workbuddy_proposals.py`、`pages/WorkBuddy/Workflows|Proposals|Approvals`、`layouts/*`、`routes/*`。B 线文件只读，跨线只经 `Resolver(actor, …)`（B-04）调用。
4. 迁移编号只用 **031–049**；`errors.py` **只追加**；i18n 只用 `workflow.*` / `inbox.*` / `proposal.*` 且中英同步；CHANGELOG 只追加自己条目。
5. **禁止**为通过门禁而放宽断言、跳过测试或删除既有测试。
6. 产品/合规决策**不自行假设**：写进 `docs/plan/ledger/integrator.json` 的 `blocked`，跳过该子任务、其余继续。
7. 每批次一个 PR；推送信息用详细简体中文（背景 / 根因 / 改动 / 可复现证据 / 验证命令与结果 / 未包含项）。

## 每批次完成标准（全部满足 + 留下可复现证据，才算完成）

- 后端：`uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy src/octop` 全通过；
- 迁移三态（涉及迁移时）：既有库可升级且数据完好、全新 PostgreSQL 可建、全新 SQLite 不报错；并给出**数量对账 + 抽样检索对比**；
- 前端：`npm run lint` 0 error、`tsc -b`、`vitest run` 通过（涉及前端时）；
- 界面改动：用真实服务跑一次人工冒烟并留证据；
- 状态写回 `docs/plan/ledger/machine-a.json`（该批次 `done` + PR + 提交 + 证据）。

## 批次（顺序执行，不得跳批）

| 批次 | 任务 | 说明 |
|---|---|---|
| 1 | A-01、A-19、A-20、A-21 | 前端 IA 重组（工作流详情页做中枢、去个人版痕迹）+ 三个小缺陷修复 |
| 2 | A-04、A-05、A-02、A-03 | 节点元数据契约 + 编译器诊断聚合 + 运行详情增强 + 版本 diff |
| 3 | A-06、A-07 | 创建向导（实时校验 + 试运行）+ 节点集显式化 |
| 4 | A-08、A-09、A-11 | `ask` 人类表单节点 + `waiting_input` + `resume` + 产出审核 + 收件箱三合一 |
| 5 | A-12、A-13、A-14、A-15 | 纠正采集 + 归因 + 分析器 + Agent 生成工作流（受限 DSL + 编译闭环） |
| 6 | A-16、A-17、A-22、A-23、A-24 | 画布（React Flow）+ Chatflow + 触发器投递 + outbox 传输 + 租户级指标 |

关键路径：`A-05 → A-08 → A-14 → A-15`（不得因并行而打乱依赖）。

## 两机协作（与线 B 并行）

- 批次 1–2 与线 B 的 B-01…B-04 并行；**合并顺序**：先合 A 线无迁移批次（A-01…A-07、A-19…A-21）→ 再合 B-01…B-07 → 然后 A-08+ 与 B-08+（契约 7）。
- 本机是**集成者**：两机同一批次都 `done` 后，由本机跑该批次验收、修集成问题、把 `integrator.json` 的 `next_batch` 推进。
